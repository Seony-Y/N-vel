# N-vel

AI 용의자를 심문하고 단서를 모아 범인을 지목하는 추리 게임.
Next.js 16 + Neon(PostgreSQL) + Drizzle + Better Auth + Claude API. 기획은 [docs/PLAN.md](docs/PLAN.md).

## 시작하기

1. https://neon.tech 에서 프로젝트를 만들고 접속 주소(`postgresql://...`)를 복사한다.
2. `.env.example` 을 `.env.local` 로 복사하고 값을 채운다.
3. 실행
   ```bash
   npm install
   npm run db:migrate   # 테이블 생성
   npm run seed         # content/cases/*.json 공식 사건 넣기 (같은 slug 는 덮어씀)
   npm run dev          # http://localhost:3001
   npm run check        # Neon·Claude API 연결 확인
   npm run admin -- <이메일>   # 관리자 지정 (--remove 로 해제)
   npm run test-account        # 이메일 로그인용 테스트 계정 (정보는 .env.local 의 TEST_ACCOUNT_*)
   ```

`.env.local` 의 `MOCK_AI=true` 이면 Claude 를 호출하지 않고 테스트 응답을 보낸다 (비용 0).
테스트 응답에서도 입력에 단서 이름의 단어가 있으면 단서를 찾은 것으로 처리해 게임 흐름을 시험할 수 있다.

## 구조

```
content/cases/         공식 사건 파일 (JSON). 형식은 src/lib/cases/format.ts
src/db/schema.ts       DB 스키마 (사건, 장소, 용의자, 단서, 무너지는 지점, 플레이 기록)
src/lib/cases/         사건 파일 형식(format.ts), 저장·내보내기(import.ts), 자동 점검(check.ts), AI 검수(review.ts)
src/components/case-editor/  사건 에디터 (탭 7개)
src/app/api/cases/     사건 저장·수정·삭제, 검수
src/lib/game/
  load.ts              사건·플레이 기록 불러오기
  rules.ts             게임 규칙: 찾을 수 있는 단서, 증언 공개 조건, 증거 제시, 채점
  prompts.ts           나레이터·용의자 프롬프트, <clue> 태그 처리
  public.ts            화면으로 보내도 되는 값만 골라내기 (정답·비밀 제외)
  session.ts           API 공통 처리, 진행 상황 저장
src/app/api/play/      시작, 조사·심문(act), 이동, 잠금 해제, 메모, 힌트, 추리 제출
src/app/cases/[id]/    사건 소개 + 수사 시작 (/edit: 에디터)
src/app/my/cases/      내가 만든 사건
src/app/my/plays/      내 수사 (수사 중 / 해결 / 해결하지 못한 사건)
src/components/CaseActions.tsx  진행 상황에 맞는 버튼 (이어서 수사하기 / 결과 보기 / 다시 도전 / 수사 시작)
src/app/play/[id]/     플레이 화면, 결과 화면
src/lib/ai/            모델 목록, 테스트 응답, 사용량 기록
```

## 핵심 원칙: 진실은 데이터가 정한다

- 범인·진상·단서·용의자별 정보는 사건 데이터에 있다. AI 가 지어내지 않는다.
- AI 는 응답 끝에 `<clue>C3</clue>` 로 단서 발견을 **요청**만 한다. 서버(`rules.ts`)가 조건을 확인한 것만 인정한다.
  - 장소 단서: 지금 있는 장소 + 선행 단서 충족 + 잠금 아님
  - 증언 단서: 그 용의자가 가진 것 + (무너지는 지점이 있으면) 그 지점이 무너진 뒤
- 증거 제시로 무너지는 지점(breakpoint)은 AI 판단이 아니라 서버가 정한다.
- 용의자마다 프롬프트를 따로 만든다. 범인이 아닌 용의자의 프롬프트에는 진상이 없다. 나레이터는 범인을 모른다.
- 화면으로 보내는 값은 `public.ts` 를 거친다. 비밀번호·정답·못 찾은 단서는 절대 보내지 않는다.
- 진상은 추리를 제출한 뒤 결과 화면에서만 공개한다.

## 사건 만들기

- 상단 "사건 만들기" → 새 사건. "예시 불러오기" 로 테스트 사건(막이 내린 뒤)을 불러와 고쳐 볼 수 있다.
- 장소·용의자·단서는 자동으로 코드(L1, S1, C1, T1)가 붙는다. 수정해도 코드가 같으면 id 가 유지되어 진행 중인 플레이가 이어진다.
- 검수: 자동 점검(무료, 선행 단서 순환·비밀번호 단서 유무 등)과 AI 검수(Opus, 1회 약 $0.1, 시간당 10회).
- 비공개 사건은 만든 사람만 보고 플레이할 수 있다. 19세 사건은 성인 인증이 준비될 때까지 공개 불가.
- 공식 사건(content/cases/*.json)은 화면에서 수정할 수 없다. 파일을 고치고 `npm run seed`.

## 가입·크레딧

- **새 가입은 구글 로그인만** (GOOGLE_CLIENT_ID/SECRET). 가입 즉시 보너스 700 크레딧 (한 사람 한 번)
- 이메일·비밀번호 로그인은 기존 계정(운영자, 테스트 계정)용. 같은 이메일로 구글 로그인하면 같은 계정에 연결된다
- 비밀번호 찾기·재설정은 이메일 계정만 (메일 발송: Resend. 키가 없으면 서버 콘솔에 링크 출력)
- 회원 탈퇴: 계정 설정에서 확인 문구 입력 + 최근 15분 안에 로그인한 세션만. 모든 데이터 삭제
- 임시 메일 도메인 가입 차단, 한 IP 에서 시간당 가입 5회·로그인 분당 10회 제한 (DB 의 rate_limit 테이블)
- 조사·심문 1회마다 모델별 크레딧 차감 (AI 호출 전에 차감, 오류 나면 환불). 잔액이 모자라면 행동 불가
- 모든 잔액 변경은 credit_ledger 에 기록. 관리자는 사용자 화면에서 지급·회수 가능

## 관리자 (/admin)

- 기간별 가입자·플레이·해결률·차감 크레딧·API 원가·오류 집계, 사건별·사용자별 표, 최근 이벤트
- 사용자 상세: 플레이마다 모델·점수·일치율·크레딧·원가·오류
- 플레이 상세: 전체 대화, API 호출별 토큰·원가, 캐시 적중률, 제출한 추리 vs 정답, 정답지
- 기록 위치: `usage_logs`(호출별 토큰·원가), `event_logs`(오류·AI 거절·규칙 밖 단서 요청·응답 잘림), `play_sessions`(크레딧·점수·일치율)
- 정답지(/cases/[id]/answer)는 만든 사람과 관리자만 볼 수 있다
- 내부 가격 기준: `docs/PRICING.md` (git 에 올리지 않는 로컬 문서)

## 채점

범인 50점 + 객관식(흉기·동기 등) 30점 + 결정적 증거 20점(최대 3개 선택) - 힌트 1개당 10점.
범인을 맞히고 80점 이상이면 "사건 해결", 범인만 맞히면 "부분 해결", 범인을 틀리면 "미제", 수사를 포기하면 "미제(수사 포기)" (진상 공개, 사건별 포기 엔딩).
수사 중에 "처음부터" 를 누르면 진행 중이던 기록은 포기로 처리된다. 끝난 사건은 언제든 다시 도전할 수 있다. 기준은 `src/lib/game/rules.ts` 의 SOLVED_SCORE.
추리 일치율 = (범인 1 + 객관식 문항 수 + 증거 칸 수) 중 맞힌 비율.

## 토큰 절약

| 항목 | 방식 |
|---|---|
| 규칙 + 사건 개요 + 역할별 정보 | 캐시 지점 1 (스레드마다 고정) |
| 이 스레드의 대화 | 캐시 지점 2 (뒤에만 추가) |
| 현재 장소, 찾을 수 있는 단서, 인정한 사실 | 캐시 지점 뒤의 system 메시지 |

`usage_logs` 의 `cache_read_tokens` 가 계속 0이면 캐시가 깨지고 있다는 뜻.
